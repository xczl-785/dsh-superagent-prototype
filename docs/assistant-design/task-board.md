## 当前基线与推进约定

- 助手首版及 Windows 路径适配已提交至 `dev`，提交 `87ac096`；已有真实工具、工单、反馈与持久化实现，不使用展示用假数据。模拟检查与真实使用验证分别记录。
- 用户已安装桌面插件，客户端已恢复并补入目录配置；当前缺少 GitHub 配置，助手实际对话及执行闭环尚未试用。缺少配置时按钮可点击并指向未创建会话的问题，归 A01。
- 保留 GitHub 配置为助手使用前提；不增加未配置 GitHub 时独立启动助手的需求。
- 每个编号是独立需求，单独明确范围、验收和估计，内部可以分阶段交付。总路线图、下一批推荐和分阶段计划均不表示全部事项已经进入开发。
- 用户已接受 [下一批渐进式计划](next-batch-plan.md)，按 A01 → A03 → A04 分别推进与交付；其余候选不自动进入开发。
- 测试沿用用户约定：不接管桌面，不使用影响电脑操作的测试；DSH SS 和不可用的 GitHub 边界可模拟。真实模型、客户端与渠道联调未进行时明确保留验证缺口。

## 推荐下一批及后续选择

推荐顺序为 **A01 → A03 → A04**，合计粗估 **2.5～5 人日**。这三项分别交付、验收和收束，不合并成一个大需求；第一项完成即可停止或转入用户试用。选择理由与各需求内部阶段见 [下一批渐进式计划](next-batch-plan.md)。

完成这一批后，再依据实际反馈选择 A02、A06、A07 等需求。A05 若成为真实试用阻断，可调整到前面；它不因被列入任务板就自动纳入本批。附件、外部操作和个人记忆也不随本批自动启动。

## 状态维护

需求开始时，在本表更新状态并链接其具体方案；完成时记录实际交付与检查依据。设计方向或边界变化仍更新对应设计文档，实现状态更新 prototype.md，本表只保留足够判断下一步的摘要。等待环境或用户试用时写清依赖，不把未验证标记为已完成。
