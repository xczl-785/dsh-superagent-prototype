## 任务板准入与验证方式

新增或重新启用实现项时，应能说明：哪个场景存在什么具体支撑不足、现有能力为何不能恰当满足、要补什么可调用能力或具体合同，以及怎样检查其真实效果。对象语义不清、调用不可靠或使用成本明显妨碍协作，也可以构成支撑不足，不要求先证明绝对无法完成。尚不能定位时，保留为场景走查或能力核查，不先转成开发任务。

验证分层：工具和运行合同用相称的自动化检查；能力可达性核实真实注册/权限与调用入口；agent 的理解、判断、工具选择和协作效果用行为走查或适用的模型验证。行为未验证不等于机制缺失，工具检查通过也不等于 agent 整段行为得到机制保证。继续遵守不影响桌面的测试限制。
