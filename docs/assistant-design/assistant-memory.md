# 助手记忆：沉淀、使用与维护

本文件维护已确认的助手记忆能力要求及可选扩展。与项目资产、原始对话的内容分界由 [foundations.md](foundations.md) 维护；本文件不重复维护项目事实。以下是设计要求，尚无记忆系统实现或运行验证。

## 默认沉淀意识

agent 主动识别有持续协作价值的信息，不依赖用户每次提醒“记一下”。项目要求和决定进入项目资产；适合跨对话延续的个人协作信息进入助手记忆。本次交流的进度和细节可以留在对话及接续上下文，不自动升级为长期记忆。

记忆需要能区分用户明确表达的信息与 agent 推断的倾向。前者在适用范围内使用，后者作为参考，不升级为用户要求；依据不足可以不保存。不要求复杂评分，但应能追溯来源、理解范围并判断是否仍有效。

默认指令说明归属、责任与基本时机，可用工具/接口支撑操作，skill 可以提供维护方法。单靠提示词不能保证实际沉淀，具体载体组合尚未决定。

实现分界遵循 [design-focus.md](design-focus.md#已确认的助手形态与实现分界)：识别值得记忆的信息、按需查询、判断适用性和选择修正是 agent 自主行为；系统支撑真实可用的查询/写入/维护能力及来源、范围、有效性和忘记等操作语义。下文的闭环用于走查能力是否足够，不要求编码自动提炼、强制检索或固定读写顺序。工具/说明已足够时，不因列出了场景就新增流程。

## 基本操作

| 能力 | 要求 |
| --- | --- |
| 查询 | 能发现与当前问题相关的记忆，并按适用项目或情境限定范围 |
| 新增 | 保存有持续价值、且没有合适已有归属的新信息 |
| 修正 | 用户纠正或出现新依据时更新已有认识，保留必要来源 |
| 停用 | 不再适用的内容退出默认使用范围 |
| 删除 | 用户要求忘记时移除对应助手记忆 |

相近内容优先检查是否应更新已有记忆，避免不断追加重复条目。当前明确要求优先；一次情境性例外不自动覆盖长期偏好。

用户可以询问记住了什么、纠正或要求忘记。日常无需逐条审批；形成或改变重要协作偏好时可简短告知，不固定呈现脚本。

删除助手记忆与删除原始对话是两项不同操作。用户要求忘记的内容，不应通过后台提炼旧对话又自动写回。具体落实方式尚未设计。

## 获取与使用闭环

基本闭环为：`交流中识别并沉淀 → 后续按需获取 → 判断适用性 → 用于协作 → 根据新信息修正`。

- **可发现**：按当前问题查询，不要求每次加载全部记忆。
- **可核对**：查询结果能表达内容、适用范围、来源与有效性；需要时可以继续查看原始交流。
- **可维护**：使用时发现不准确、范围不合适或已被替代，可以修正或停用。

搜到表示相关，不代表应当遵循。用户当前明确要求优先；推断记忆仅辅助判断；工程事实仍从当前项目资产获取。

不规定固定检索频率、返回条数或读取顺序。是否有少量偏好默认加载，仍是后续选择。上述信息要求不等于已选定数据字段、检索算法或数据库。

## 可选扩展：从对话回顾提炼记忆

用户认可将其作为扩展：先完善基本记忆工具和操作闭环，再根据实际遗漏、重复或误归类需求考虑封装 skill。当前未创建该 skill，也未选定后台自动触发机制。

其候选职责是回顾和校正：发现值得保留的协作信息，排除项目事实与一次性要求，对照已有记忆识别新增、修正、重复或冲突，给出来源和范围。可以没有新增记忆；复用基本记忆能力，不建立第二份存储，也不接手项目资产整理。

用户主动要求时可调用；出现有价值的遗漏或偏好冲突、准备结束或切换交流且存在待整理信息时，agent 可判断是否回顾或提议。需求探索结束本身不强制触发，不每次询问是否运行 skill；提议应说明具体价值。

触发回顾不等于全部候选都写入。不确定推断可以保留为候选、询问或放弃，不要求批量批准，也不要求为了收尾产生记忆。

## 状态与来源

上述基本操作、获取使用闭环与维护原则均来自本次用户逐项接受的讨论；回顾提炼仅作为可选扩展。用户关心向量化频率，提出过记忆与数据库分开的可能性，未形成技术决定。

未决选择集中在 [interaction-proposals.md](interaction-proposals.md)。不因本文件形成便进入实现阶段。
