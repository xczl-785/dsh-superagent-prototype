## 先认识现在的助手

助手是本项目的协作对话入口。你可以让它查看实际工程文件、分析问题、比较方案，讨论本身不要求建单。决定实施后，它把选定要求交给后台执行者（worker），以工单记录工作；问题和结果再返回助手，供你继续讨论。

以下是已实现的基础能力；真实模型选择工具及实际客户端效果仍待试用：

| 你想做什么 | 现有实现能做什么 |
| --- | --- |
| “先看看问题，讨论一下方案” | 读取项目依据、分析和维护相关文档；不自动把全部聊天发给执行者 |
| “按这个决定开始做” | 引用真实用户消息创建工单，交接范围、背景和来源，查询派工及当前状态 |
| “给刚才那项工作补充一点” | 指定工单追加信息；可携带当前问题编号答复，过时编号会拒绝 |
| “那项工作怎么样了？” | 查询真实工单，也可要求执行者报告状态；需要沟通的问题和结果返回助手 |
| “停止”或“重试失败的工作” | 通过现有工单规则停止或重试；停止不能撤销已发生的外部操作 |
| “上次聊到哪里了？” | 查询原始对话，读取一份讨论接续记录，再核对当前工单和项目文件 |

你正常说话即可，工具名称和消息编号由助手处理。能调用工具不表示模型已经在真实使用中正确完成所有理解；本批补信息入口和操作约束，不用预写对话或假数据代替实际能力。

## 选什么，为什么这样排

原建议为 **A02 → A06 → A07**，人工等效粗估合计 **2.5～5 人日**。该排序未充分映射资产和记忆闭环，已撤下；估计只保留为历史粗估，不作为当前工期或进入承诺。

| 顺序 | 功能的直白说法 | 解决的问题 | 粗估 |
| --- | --- | --- | --- |
| A02 | 关掉再回来，助手还能正确接上 | 插件重载、会话归档或删除、工作目录改变时，入口和实际会话归属一致 | 1～2 天 |
| A06 | 你的答复准确送到那项工作 | 区分一般补充与回答待决问题，避免串单、答旧问题或误清除问题 | 0.5～1 天 |
| A07 | 找回“上次为什么这样决定” | 直接定位已知消息及邻近讨论；接续记录说明来源和更新情况 | 1～2 天 |

上述原排序着重会话和工单沟通，未覆盖原始目标全貌；不能据此把资产维护和基本记忆持续后置。以下仍说明这些候选各自可能解决的问题。

## A02：关掉再回来，助手还能正确接上

**现在已有：**启动时按项目状态目录确定助手会话，尝试恢复已有会话；没有时创建。工单和接续记录保存在插件数据库。尚未明确覆盖归档、运行中删除及工作区变化。

**使用例子：**昨天讨论导出功能并交接了一项工作，今天重开客户端。助手应接回对应项目，你能继续问工作情况；如果会话被删除，应明确告诉你发生了什么，不再指向不存在的会话。

**建议规则，待本批对齐：**

- 正常重开、插件重载：复用原助手会话，恢复必要工具和指令；按当前工单解释进度，不重复建单。
- 已归档：区分归档与删除，在用户主动打开助手时恢复访问。先核实 Harness 本地接口；不支持时明确提示实际可用的恢复路径。
- 已删除：说明会话缺失，提供显式重建路径，不静默恢复已删除的对话。重建可读取仍存在的工单与接续记录，不能声称恢复了被删除的历史。
- 修改项目目录：识别已有会话实际目录与新配置不一致，说明原因并阻止向错误工程继续交接。本批给出恢复正确配置的操作说明，不自动搬迁历史、工单或切换项目。
- 会话不可达：反馈保留在现有投递队列，入口据实显示；不为投递反馈自动另建助手对话。

**阶段与验收：**先核实本地宿主对归档、删除、恢复、工作区的接口和可观察状态，再落实规则；模拟覆盖重载、归档、缺失、目录不匹配及待投递反馈。没有宿主事实时，不能把所有解析失败都解释成已删除。

**你得到：**可解释的重新进入与恢复行为。恢复会话不等于自动重试执行，删除对话也不等于删除工单。

## A06：你的答复准确送到那项工作

**现在已有：**能定向追加到某张工单，可带问题编号核对是否过时。一般补充和问题答复共用接口，问题编号可省略，语义还不够明确。

**使用例子：**导出工作问“旧格式保留吗？”，界面工作问“布局用哪版？”。你说“导出保留旧格式，界面再讨论”，应只把前半句作为导出问题的答复，后半句留在讨论中。

**本次补齐：**

- 区分“给工作补充资料”和“回答工作正在等待的问题”；答复关联工单及当前问题，助手负责取得标识。
- 核对问题是否仍有效。已被替换、解决或工单结束时，返回当前事实，让助手重新核对。
- 一般补充不被当作回答；有效答复进入工单输入流程后，按现有执行规则更新问题状态。入队、投递和执行者读取仍分别表达。
- 同一答复重试不产生重复输入，扩大范围仍需新工单。

**阶段与验收：**先核查问题状态和输入处理规则，再明确工具合同及必要提示词引导；覆盖双工单并行、普通补充、当前答复、过时答复与重复投递。工具校验标识，不能替模型保证自然语言理解；上下文确实无法确定目标时需要澄清。

**你得到：**在助手这里讨论并答复，执行者拿到准确决定，无需你转述整段聊天。

## A07：找回“上次为什么这样决定”

**现在已有：**原始历史可分页或按关键词搜索；助手可替换保存一份项目讨论接续记录。尚无按消息引用直接定位并读取邻近讨论的入口，接续记录的更新时间和依据也不够完整。

**使用例子：**讨论了几个话题后，你问“导出不是说只修编码、不改格式吗？”。助手能找到当时决定及前后讨论，区分用户决定和自己的旧建议，再检查当前工程文件有没有变化。

**本次补齐：**

- 根据原始消息引用定位历史，读取其前后有限范围；保留关键词查询。原消息缺失时明确说明，不补造记录。
- 接续记录带更新时间和来源引用，保留目标、已接受决定及未决问题；继续维护一份当前记录。
- 在关键决定或交接时保存必要线索，恢复时结合当前工单和工程资产核对；不规定每轮聊天都自动生成摘要。
- 多话题切换后，能按所问主题查回依据，避免把另一项工作的结论套过来。

**阶段与验收：**先定义消息定位及邻近窗口合同，再补接续元数据和恢复引导；覆盖已知消息、关键词不足、原文缺失、多话题、旧记录与当前事实不一致，并验证旧接续记录仍能读取。继续复用 Harness 原始会话持久化与已有数据库。

**你得到：**助手有途径找回讨论依据并接续协作。长期个人偏好记忆仍属于 A11，不承诺把全部历史永久装进模型上下文。
