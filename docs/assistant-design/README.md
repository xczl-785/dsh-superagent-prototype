# 项目协作助手：设计与原型入口

本文集面向设计、开发、评审和维护助手功能的 agent，供用户审阅；不是给运行中助手加载的背景或提示词集合。文中的“助手”是被开发的产品角色，“开发 agent”是阅读这些资产并修改项目的执行者。更新日期：2026-11-05。

## 开发接续入口

首次开发接续先读 [形态、目标和实现分界](design-focus.md#已确认的助手形态与实现分界)，理解系统位置和已有后台，再按任务读取信息边界、记忆要求或实现事实，最后用任务板确认具体缺口。熟悉背景后的局部工作可直接进入对应归属，不要求每次通读全部历史。

开发时区分 agent 自主行为与系统支撑：场景用于走查，只有具体信息、工具、合同或运行缺口才形成实现项。文档对架构、位置及后台的解释服务开发判断，不能据此增加运行时背景注入任务。运行提示词及工具说明的具体设计与验证属于实现工作。

| 读者当前要做什么 | 阅读归属 |
| --- | --- |
| 理解助手是什么、位于何处、目标和分责是什么 | [design-focus.md](design-focus.md)：设计约束的维护归属 |
| 明确项目资产、助手记忆和原始对话的责任及沉淀/获取原则 | [foundations.md](foundations.md)：信息边界，不复制项目现状 |
| 设计记忆操作与使用支撑 | [assistant-memory.md](assistant-memory.md)：已确认要求与仍待选择的技术 |
| 了解当前插件接入、工具合同、使用及验证限制 | [prototype.md](prototype.md)：实际实现事实；部署细节见 [006 Deployment](../006-deployment.md) |
| 确认已交付支撑、具体缺口、待核查项和可选方法 | [task-board.md](task-board.md)：当前工作状态，不把每行当作开发需求 |
| 理解助手实施前的工程基础和静态依据 | [current-system.md](current-system.md)：明确基线的参考，不作为当前代码结论 |
| 比较早期备选机制或复查概念走查 | [interaction-proposals.md](interaction-proposals.md)：保留候选理由，不自动成为当前规格 |

根目录保留持续维护的设计、实现说明及工作状态；`history/` 保存已交付计划、已撤下建议和已完成审视的证据，避免被文件名误导为当前开发指令。历史未决项不因归档自动解决；有效要求和当前缺口仍在上面的维护归属中。

| 记录 | 保留用途 |

## 来源、证据与维护

需求讨论来源为 Codex 对话（2026-11-02 至 2026-11-03），原型范围、agent 自主原则和本目录的开发读者于 2026-11-05 接续确认。本目录是提炼资产，原始完整对话未导出到仓库；当前设计背景并非运行助手的长期记忆。

变更时改写主题的维护归属，再修复受影响入口和链接；不在本入口复制需求清单或追加流水账。区分已确认目标、待选机制、实现事实及验证结论；文档中的授权背景不替代实际操作授权。
