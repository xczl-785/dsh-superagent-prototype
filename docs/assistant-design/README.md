# 项目协作助手：讨论入口

本文集保存个人 fork 的协作助手设计，供用户和冷启动 agent 接续。部分目标与能力要求已确认；具体实现尚未批准或完成。上游产品说明仍在父目录的编号文档中。

## 当前目标与阅读路径

希望在现有偏执行的 superagent 之上，提供理解工程、沟通想法、澄清问题和形成有效产出的协作能力。当前目标与责任边界以 design-focus.md 为准。

| 读者当前要做什么 | 阅读归属 |
| --- | --- |
| 理解这个 agent 的目标、能力、自主性、活跃方式和职责边界 | [design-focus.md](design-focus.md) |
| 区分项目资产、助手记忆和原始对话；理解沉淀/获取时机与已有基础 | [foundations.md](foundations.md) |
| 继续讨论助手记忆的写入、使用、修正、忘记和可选回顾 skill | [assistant-memory.md](assistant-memory.md) |
| 了解现有 superagent 能力及静态源码依据 | [current-system.md](current-system.md) |
| 查看剩余方案、概念走查及继续讨论的条件 | [interaction-proposals.md](interaction-proposals.md) |

首次接续先读本入口和 design-focus.md，再按问题选择其他文件，不要求每次通读全部资料。直接浏览目录时，各文件标题与上述职责一致。

## 整体盘点

| 方面 | 当前结论与边界 |
| --- | --- |
| 已确定 | 目标、六项能力及职责；agent 自主组织工作；按需活跃、允许相关事件唤起；不承担全程执行或全面项目管理 |
| 已确定 | 项目资产与助手记忆分工；默认主动沉淀与 agent-docs 意识；原始对话查询和工作来源线索作为恢复兜底 |
| 已确定 | 助手记忆的查询/新增/修正/停用/删除、按需获取和适用性判断、使用中修正；回顾提炼为可选扩展 |
| 已确定形态 | 单项目、一个主要助手对话＋并行工作状态可见性；复用现有界面仍待设计，多对话移出范围 |
| 已确定分责 | 协作助手与原主 Session 的后台调度职责分开；调度会话默认隐藏，高级设置可显示，不改变后台运行 |
| 已确定操作边界 | 对话正常交互，影响操作通过工具/接口；不把整段助手交流订阅给工单。feature 仅为使用语义，不新增插件实体或生命周期 |
| 沿用工程基础 | DSH 会话/模型/工具/工作区，以及 superagent 的来源、工单、执行和反馈机制；事实证据见 current-system.md |
| 用户提供的基础 | docs-workflow 协调文档维护，RouteLedger 承接适用的阶段与推进记录；按能够接入使用评估，尚未在本仓库完成接入 |
| 需补齐或核验 | 协作角色可用的记忆操作入口、原始对话定位/搜索入口、交接来源关联、相关结果可达与唤起能力；此处列能力缺口，不断言必须全新开发 |
| 待选择 | 底层会话/上下文机制、面板布局与信息关联、接口及角色接入、记忆存储与检索实现、可选 skill 的正式封装；没有选定向量库 |

本轮没有确认还需新增一套资产治理、项目管理或执行调度系统。已有基础的可复用范围与适用限制在其对应文档维护。

## 当前阶段与下一步

- 已完成目标与能力层对齐、初步覆盖检查和跨数日概念走查，记忆能力层闭环基本齐备。概念走查不是产品运行验证。
- 当前在整体收束与需求层盘点，尚未实施协作助手、记忆系统或新接口。
- 已完成与现有对象和接口的静态核对：主要场景无需新增 Feature 对象，新工作来源和定向输入接口仍需适配；不能把现有能力误记为助手已接通。
- 下一步讨论现有面板如何复用，围绕真实工作对象与状态组织，不重开多对话或 Feature 建模；具体接入和技术实现后定。
- “延续协作上下文”仍是后续设计重点。具体接入、文档工作流内部改造及存储技术选型继续暂缓。

后续讨论保持目标和能力边界，以使用走查发现信息不可达、能力缺失和职责冲突，不编排 agent 的常规判断与对话步骤。多助手对话已移出当前范围；底层上下文恢复仍可讨论。当前设计重心的完整内容只在 design-focus.md 维护。

## 来源、证据与维护

讨论来源为本次 Codex 对话（2026-11-02 至 2026-11-03）：涵盖目标、能力、信息与记忆准则，以及单助手形态、后台调度分责和既有对象/接口兼容核对。本目录是对话提炼，不是逐字记录；原始完整对话未导出到仓库。

- `foundations.md` 记录用户明确接受或明确纠正后的结论；相关用户原意在文内注明。
- `current-system.md` 记录本次静态检查支持的行为，附仓库源码引用，不代表运行验证。
- `design-focus.md` 记录最新讨论的目标、候选方向与评价依据，尚非最终规格。
- `assistant-memory.md` 维护助手记忆要求及可选扩展，与项目资产规则分开维护。
- `interaction-proposals.md` 保留助手提出但用户尚未逐项接受的设计，不能直接作为实施授权。

本轮正在以项目资产方式保存讨论，尚无独立的跨会话助理记忆。更换会话时，可从此入口接续。

后续在对应文件中改写有效结论和待决问题，保持一项内容一个维护归属；不在入口追加一套重复的需求或会话流水账。文档中记录的授权背景不替代实际操作授权。
